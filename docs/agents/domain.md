# Domain Docs

This repository uses a single-context domain layout:

- `GLOSSARY.md` at the repository root defines domain vocabulary.
- `docs/adr/` contains architectural decision records.

Before exploring a topic, read the root glossary and the ADRs relevant to the
area being investigated. If either is absent, proceed without requiring it to
be created upfront.

Use glossary terms when naming domain concepts in issues, proposals,
hypotheses, and tests. If a useful term is missing, note the gap for
`/domain-modeling`.

If a proposed change conflicts with an existing ADR, identify the conflict
and explain why the decision may need to be revisited.
